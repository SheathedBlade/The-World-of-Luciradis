# Impeccable Design Context

This file captures persistent design guidance for the Luciradis wiki project. It is the authoritative reference for all future design decisions in this repository.

---

## Design Context

### Users

**Primary:** The author (yourself) — a worldbuilder maintaining Luciradis as a personal creative archive spanning characters, locations, events, lore, and first-hand records across multiple narrative eras.

**Secondary:** Interested public viewers who discover the wiki through the live site (luciradis.terystal.dev). These readers may have no prior knowledge of the world and rely on the wiki's structure, navigation, and in-text linking to orient themselves.

**Context of use:** Self — drafting and refining entries in Obsidian. Public — reading served articles via Quartz. Both modes should feel equally considered.

### Brand Personality

**Voice:** Scholarly, authoritative, yet emotionally warm. Entries read like institutional archive records with occasional editorial voice from Head Archivist Kallie Myrai (`_// K.M. edit //_` annotations). Tone is mythic and world-worn, not clinical or dry.

**Personality (3 words):** Archival — Lore-dump — Mythic.

The wiki should feel like an ancient repository that has been lovingly maintained and annotated over millennia, not a generic flat-file site.

### Aesthetic Direction

**Core feel:** A warm, scholarly archive with parchment/aged-document undertones — not sterile, not overly decorated. Distinct from the default Quartz aesthetic; the goal is a site that feels like it has a sense of history and craft.

**Light mode direction:** Warm bone/parchment backgrounds (`--lightbone: #e6e0cb`, `--bone: #d8d8c3`, `--warm-white: #fffbf5`) with deep readable text. The light theme should feel like aged vellum and ink — scholarly but inviting. Emphasis on readable hierarchy via font weight and the custom color variables, not heavy ornamentation.

**Dark mode direction:** Deep, dramatic darks with warm amber/gold accents (`--bright-yellow: #f5d69c`, `--warm-white: #fffbf5`). The dark theme is the more dramatic presentation — a scholar's reading room at night, candlelit. Stronger color contrast in headers and UI chrome. More visual "flair" is appropriate here.

**Current palette (reusable in Obsidian via CSS variables):**
- `--sakura: #cc2364` — primary accent (pink)
- `--pink: #f19bbc` — secondary accent
- `--green: #3eb4bf` — info/teal accent
- `--yellow: #e5b567` — highlight/warning accent
- `--orange: #e87d3e` — tertiary accent
- `--blue: #496d9e` — cool contrast accent
- `--purple: #b986c8` — decorative accent
- `--deepred: #e67e80` — dark theme emphasis
- `--emerald: #39b684` — progress/success accent
- `--bright-yellow: #f5d69c` — dark-mode highlights
- `--warm-white: #fffbf5` — dark-mode text
- `--cool-gray: #7d7d7d` — muted text
- `--lightbone: #e6e0cb` — light background
- `--bone: #d8d8c3` — light surface

**Typography (current — do not change without review):**
- Titles: **Plus Jakarta Sans Variable** (700 weight)
- Headers: **Lexend** (500, 600 weights, italic enabled)
- Body: **Satoshi Variable**
- Code/metadata: **Azeret Mono**

**Anti-references:**
- Generic Quartz/default wiki aesthetic — the site must not look like an out-of-the-box Quartz install.
- Overly minimal / brutalist — the content has emotional weight; the design should carry warmth, not just function.
- "Modern SaaS" look — no blue/purple gradient hero sections, no corporate card grids.

### Design Principles

1. **Archival warmth over minimalism.** Every design decision should ask: does this feel like a scholarly repository with centuries of accumulated knowledge? Warmth and readability beat pure minimalism.

2. **Markdown-first flair.** All "flair" (callouts, progress bars, dialogue layouts, embed decorations) must be achievable in raw Obsidian markdown. Never add design elements that require Obsidian plugins or cannot be replicated with standard markdown + CSS snippets.

3. **Distinct light and dark personalities.** Light mode = refined parchment archive. Dark mode = dramatic candlelit reading room. Both equally supported; neither an afterthought.

4. **Typography-driven hierarchy.** Structure and visual weight come from font families, sizes, and weights — not from heavy borders, shadows, or decorative chrome. The existing heading color hierarchy (sakura H2s, pink H3s, yellow H4s, etc.) is a core asset.

5. **In-world voice is part of the design.** The `_// K.M. edit //_` editorial annotations and the fictional "Luciradis Knowledge Database" framing are not content quirks — they are part of the site's identity. Design elements should respect and reinforce this voice.

## Design Assets

### Custom Obsidian Callouts (already implemented)

These callout types are in use and must continue to work in Quartz:

| Callout | Purpose | Visual treatment |
|---|---|---|
| `dialogue-left` | Narrative dialogue, left-aligned | Italic, no border/icon, right-padding offset |
| `dialogue-right` | Narrative dialogue, right-aligned | Italic, no border/icon, left-padding offset |
| `dialogue-center` | Narrative dialogue, centered | Italic, no border/icon |
| `dialogue-rage-left` | Angry dialogue, left-aligned | Italic, no border/icon, strong right-padding |
| `dialogue-rage-right` | Angry dialogue, right-aligned | Italic, no border/icon, strong left-padding |
| `info` | Clarifications / editorial notes | Left border in `--green`, tinted background |
| Standard Quartz callouts | Info, warning, tip, etc. | Use Quartz defaults |

### Progress Bars (already implemented)

Inline `<progress>` HTML elements are used in character dossier entries (e.g., Empyrean essence tables). Style via CSS — do not convert to images or canvas-based solutions.

### CSS Variable Architecture

Custom variables are defined in `quartz/styles/custom.scss` and mapped to Obsidian via its theme/snippet system. When adding new colors, reuse the existing palette structure:
- Prefer single-word names (sakura, emerald, bone)
- Dark mode overrides go in the `&[saved-theme="dark"]` block
- All custom variables must be valid CSS custom properties ( kebab-case)

### Fonts

Four fonts are loaded from `quartz/static/` (self-hosted):
1. `Satoshi-Variable.ttf`
2. `PlusJakartaSans-VariableFont_wght.ttf`
3. (Lexend and Azeret Mono loaded via Google Fonts in `quartz.config.ts`)

If adding fonts, place the `.ttf`/`.woff2` in `quartz/static/` and declare via `@font-face` in `custom.scss`.
